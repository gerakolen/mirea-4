Методические указания к Проектной работе
по дисциплине «Прогнозно-аналитические системы»
для профиля подготовки «Управление данными»
1. Цель проектной работы
В рамках дисциплины «Прогнозно-аналитические системы» студентам
профиля подготовки «Управление данными» необходимо спроектировать,
разработать и представить программный прототип прогнозно-аналитической
системы, обеспечивающей полный цикл работы с данными: от их получения
из внешних источников до формирования прогнозов и предоставления
аналитической информации пользователю. Разрабатываемая система должна
обеспечивать:
1. Автоматизированный сбор данных из нескольких источников.
2. Хранение исходных и обработанных данных.
3. Очистку, преобразование, объединение и подготовку данных.
4. Контроль качества поступающих и обработанных данных.
5. Построение прогнозов на основании накопленных данных.
6. Представление результатов анализа и прогнозирования в виде
интерактивных дашбордов.
7. Автоматизированное и воспроизводимое выполнение основных
процессов системы.
Особенность проекта для профиля «Управление данными» заключается
в повышенных требованиях к организации жизненного цикла данных. Помимо
получения прогноза и его визуализации студент должен продемонстрировать,
каким образом данные поступают в систему, преобразуются, контролируются,
хранятся и используются аналитическими компонентами.
В рамках проекта особое внимание должно быть уделено:
— архитектуре хранения и потокам данных;
— качеству и целостности данных;
— автоматизации загрузки и обработки;
— управлению метаданными;
— прослеживаемости происхождения данных;
— историзации изменений данных;
— устойчивости конвейера обработки данных к повторным запускам и сбоям.
Итогом проектной работы должна стать функционирующая прогнозно-
аналитическая система, позволяющая получить актуальные данные,
выполнить их обработку, сформировать прогноз исследуемого показателя и
представить результаты пользователю.
2. Выбор предметной области
Предметная область проектной работы выбирается студентом
самостоятельно и согласовывается с преподавателем в течение первых трех
недель семестра. Обязательным условием для выбранной предметной области
является:
— наличие временной составляющей данных, позволяющей решать
задачу прогнозирования;
— возможность сформулировать конкретный прогнозируемый
показатель;
— наличие не менее двух разнородных источников данных;
— возможность регулярного получения новых данных;
— достаточный объём исторических данных для проведения анализа
и построения прогнозных моделей;
— возможность определения пользователя или группы пользователей,
для которых создаётся аналитический интерфейс;
— наличие практической задачи, решение которой может быть
поддержано результатами анализа и прогнозирования.
В случае затруднения в самостоятельном выборе предметной области
студент вправе воспользоваться списком готовых предметных областей,
однако повторение темы в рамках одной учебной группы не допускается.

3. Обязательные компоненты системы
Первым обязательным компонентом реализуемой системы является
разнородность источников данных. В проекте должно использоваться не
менее двух разнородных источников данных. Под разнородностью
понимается различие способов получения или форматов представления
данных.
Дополнительные ограничения на источники данных:
1. Инкрементальная загрузка данных — повторный запуск системы
должен догружать только новые данные, ранее не записанные в
3
систему.
2. Идемпотентность — повторный запуск любой операции в системе
должен иметь одинаковый результат выполнения.
3. Устойчивость к сбоям — обработка недопустимых операций,
недоступности источников данных, таймаутов, ограничений
частоты запросов и прочих критериев, приводящих к
неработоспособности системы.
4. Журнал загрузок — информация со сведениями о каждом запуске,
параметры журнала определяются самостоятельно.
Второй обязательный компонент системы представляет собой
обработку данных, организованную в виде явно выделенных слоёв хранения с
зафиксированной ответственностью каждого слоя.
Третьим обязательным компонентом системы выступает аналитический
модуль, реализованный в виде двух дашбордов — предметного и
операционного, а также не менее двух моделей прогноза.
Общее требование к визуализации — дашборд предназначен для
принятия решения, а не для демонстрации всех доступных графиков. Каждый
элемент панели должен отвечать на конкретный вопрос пользователя.
Элементы, не отвечающие ни на один вопрос, подлежат удалению.
4. Компоненты системы реализуемые по выбору
Помимо трёх основных компонентов прогнозно-аналитической системы
студент может реализовать следующие компоненты системы уникальные для
своего профиля.
Контроль качества данных. В системе необходимо реализовать
автоматизированные проверки качества данных. Минимально должны
присутствовать проверки нескольких типов:
— полнота;
— уникальность;
— допустимость значений;
— соответствие типов;
4
— соответствие диапазонам;
— ссылочная целостность;
— актуальность данных.
Результаты проверок должны сохраняться и быть доступны для анализа.
Дополнительно необходимо определить поведение системы при обнаружении
некорректных данных.
Управление метаданными. Система должна предоставлять возможность
определить происхождение ключевых данных и показателей. Для основных
сущностей необходимо описать следующую цепочку:
Источник -> Загрузка -> Преобразование -> Слой хранения -> Витрина -> Показатель -> Дашборд
Форма реализации выбирается студентом самостоятельно. В рамках
защиты студент должен уметь показать происхождение как минимум одного
выбранного показателя от дашборда до исходного источника данных.
Историзация и управление изменениями данных. Для одной или
нескольких значимых сущностей должна быть реализована возможность
хранения истории изменений.
По согласованию с преподавателем студент может реализовать
собственные компоненты системы.
5. Технологический стек
Технологический стек студент выбирает самостоятельно и
обосновывает выбор в отчёте и презентации. Ограничений на язык
программирования, СУБД, средство визуализации, оркестратор и прочее не
накладывается: допустимы как коммерческие и облачные сервисы, так и
полностью открытые решения, как готовые BI-платформы, так и собственный
веб-интерфейс. Однако любой выбранный стек должен соответствовать
следующим требованиям:
1. Воспроизводимость — проект разворачивается и запускается
студентом самостоятельно по заранее прописанной инструкции из
README файла, прикрепленного к репозиторию.

2. Автоматизация — проект запускается одной командой,
последовательностью команд или по расписанию, без ручного
копирования файлов.
3. Конфигурируемость — обязательно использование
конфигурационных файлов и/или переменных окружения.
4. Открытость данных — используемые источники данных должны
быть общедоступными либо синтетически сгенерированными,
использование персональных данных не допускается.
